既存のPCF-PT(FPSアンカー+KNN星形トポロジー、7Dエッジ、dt符号化、9Dノード)と周辺研究(Tesla-RaptureのTemporal K-NN、StarGraphの静的中心、PCFExのStatbox、PSTNetの円筒tube)を前提に、未着手と考えられる方向を新規性の強い順に5件挙げる。各案の「近い先行研究」は把握している範囲での判断であり、投稿前に文献確認が必要(事実未確認の推測を含む)。

**1. 速度整合性エッジ特徴(物理情報に基づくクロスフレーム対応の検証)**

現在のdt符号化はフレーム変位のスカラーに過ぎない。mmWaveレーダは点ごとにradial velocityを持つため、「アンカー点の速度から予測される変位」と「実際の近傍点との変位」の残差をエッジ特徴に追加する。つまり e_residual = (p_neighbor − p_anchor) − v_anchor · dt · Δt の径方向成分。この残差が小さいエッジは同一身体部位の真の対応、大きいエッジは偶発的な空間近接であり、GATのattentionが物理的に正しい対応を選択的に重み付けできる根拠を得る。

計算コストはエッジ特徴の1〜3次元追加のみでFLOPsへの影響はほぼ無視できる。新規性の境界: Doppler速度を入力特徴に使う研究は多数あるが、クロスフレーム対応の妥当性検証信号としてエッジに埋め込む定式化は、把握している範囲で未着手(推測)。レーダ固有のモダリティ(LiDARには無い速度計測)を構造構築に使う点で、C1・C2の自然な昇華になる。

**2. アンカー間グラフ(tube間の第2階層グラフ)**

現在の星形トポロジーはアンカーごとに独立で、tube間の関係(四肢間の協調運動)を捉える機構がない。各アンカーフレームのNa=10個のアンカー特徴の上に完全グラフまたはKNNグラフを張り、軽量GAT一層で処理する。Na=10なら最大90エッジであり、コストは実質ゼロに近い。粗い「疑似骨格」抽象を学習的に得る構造になる。

新規性の境界: PSTNetの階層化は空間プーリングによる縮約であり、アンカー間の明示的グラフではない。PCFExのフレーム特徴は統計量であり関係構造を持たない。アンカーレベルの関係グラフは差別化可能と考えるが、点群動画分野(P4Transformerなど)に類似の階層attentionがある可能性は要確認(推測)。

**3. 速度依存の適応的テンポラルカーネル**

lは現在固定(l=5)。アンカー点の局所速度が大きい場合は短いl(速い動作は短窓で判別可能かつ点対応が崩れやすい)、小さい場合は長いl(遅い動作は長窓が必要)を選ぶゲーティングを導入する。実装は「複数のlのtubeを並列構築し、速度から算出したソフト重みで混合」が最も単純。matched-windowアブレーションで既にl依存性のデータを持っているため、動機付けの実証的根拠を既存実験から直接引ける点が強い。

コストは並列tube分の増加があるため、real-time制約との両立にはl∈{3,5}の2択程度に絞る設計が現実的。新規性の境界: deformable temporal convolutionは動画CNNに存在するため、「レーダ点群のtube構造への適用」として位置付ける必要がある。

**4. ストリーミング推論のためのtube再利用(システム面の貢献)**

現行のスライディングウィンドウ推論では、stride=2で隣接ウィンドウの大部分のtubeが重複計算される。アンカー特徴とエッジ特徴をフレーム単位でキャッシュし、新規フレーム分のみ増分計算するストリーミング設計にすれば、定常状態のレイテンシは大幅に削減できる(削減率は重複率に依存、要実測)。33ms/sequenceの主張を「連続動作時の実効レイテンシ」としてより強い形で示せる。

新規性の境界: incremental GNN推論は一般には存在するが、point-tube構造の増分計算はFPSアンカーがウィンドウごとに変わり得る点に固有の難しさがあり、そこを解けば貢献になる。ただしこれは精度向上ではなくリアルタイム性の強化であり、アルゴリズム的新規性は1・2より弱い。

**5. スパース性適応型アンカーサンプリング**

FPSは純幾何的で、静的クラッタと動体を区別しない。Doppler速度の大きさで重み付けしたFPS(feature-weighted FPS)により、アンカーが動いている身体部位に集中するよう誘導する。スパースなフレームで判別的な部位を確実に捕捉できる。

新規性の境界: 3DSSDのF-FPS(特徴距離FPS)がLiDAR検出に存在するため、「初提案」ではなく「mmWave HARへの速度重みFPSの適用」としてしか主張できない。新規性は5案中最弱だが、実装が最も容易で精度寄与の検証が速い。

**推奨する組み合わせ**

修士論文の次段階(あるいは次論文)としては、案1+案2の組み合わせが最も筋が良いと考える。両者とも計算コストがほぼゼロで real-time 主張を毀損せず、「レーダ固有の物理量を構造構築に使う」「星形トポロジーの欠落(グローバル構造)を補う」という現行アーキテクチャの明確な弱点をそれぞれ埋める。C1〜C3の延長線上にあり、ストーリーの一貫性も保てる。なお各案の精度寄与は現時点で全て未検証の仮説であり、小規模なパイロット実験(seed 1本、l=5固定)で当たりを付けてから本実験に進むことを勧める。
# タスク: アンカー間グラフ(Anchor-level Graph)の実装

## 背景
PCF-PointTubeでは、各アンカーフレームでFPSによりNa=10個のアンカー点を選び、
アンカーごとに星形トポロジー(KNNクロスフレームエッジ)のtubeを構築して
GATで集約している。現状、tube間(アンカー間)の関係を捉える機構がなく、
四肢間の協調運動のようなグローバル構造が失われている。

これを補うため、tube集約後のアンカー特徴の上に第2階層のグラフを張り、
軽量GAT一層で処理するモジュールを追加する。

## 実装前の確認
1. まずリポジトリ構造を探索し、以下を特定して報告せよ:
   - tube構築とアンカーごとのGAT集約が行われているモジュール/関数
   - アンカー特徴がフレーム表現に集約される箇所(現状の集約方法も報告)
   - モデル設定(config)の管理方法
2. 特定結果と実装方針を提示し、私の承認を得てからコードを変更せよ。

## 実装仕様
- 新モジュール AnchorGraphLayer を追加する:
  - 入力: 各アンカーフレームのアンカー特徴 (B, Na, D)。Na=10。
  - グラフ: 同一アンカーフレーム内のNa個のアンカー間の完全グラフ
    (自己ループなし、有向、最大 Na*(Na-1)=90 エッジ)。
  - エッジ特徴: 既存のエッジ特徴抽出と整合させる。アンカー点の3D座標を用い、
    ユークリッド距離 + x/y/z方向の単位ベクトル(既存6D方式のdt=0相当)。
    既存のエッジ特徴抽出関数が再利用できるならそれを使う。
  - 集約: 既存GAT実装と同じattention機構を1層。出力次元は入力Dと同じ。
  - 残差接続: output = anchor_feat + AnchorGraphLayer(anchor_feat)。
    これによりフラグOFF時とほぼ等価な挙動に退化可能な構造にする。
- config にフラグ use_anchor_graph (default: false) を追加。
  false のとき既存の計算経路を一切変更しないこと(後方互換必須)。
- 異なるアンカーフレーム間にはエッジを張らない(今回のスコープ外)。

## 検証
1. use_anchor_graph=false で既存テストが通り、既存チェックポイントの
   推論結果が変わらないことを確認。
2. use_anchor_graph=true で forward が通り、勾配が流れることを確認
   (小バッチのスモークテスト)。
3. FLOPs増分を thop または fvcore で計測し、baseline(16.7G)との
   差分を報告。増分は1%未満のはず。大きく超える場合は実装を疑え。
4. 推論時間への影響を計測(batch size 1)。

## パイロット実験
- 本番設定(stride=2, l=5, K=30, Na=10, 9Dノード特徴, T=62)で
  seed 0 のみ、use_anchor_graph=true で1本学習。
- 結果は results/anchor_graph/seed_0/ に保存。
  既存の results/paired_ablation/ および本番チェックポイントには
  一切書き込まないこと。
- baseline(同設定・フラグOFF)のseed 0結果と精度を比較して報告。

## 禁止事項
- 既存のtube構築・エッジ特徴・ノード特徴のコードを変更しない
  (再利用のためのリファクタリングが必要な場合は事前に提案して承認を得る)。
- 実験結果の既存ディレクトリへの上書き。
