## §1 システム定義と不変則

**定義**:思ったことを書き留めて忘れないための、信頼できる外部記憶。Obsidian vault + pull 型 skill 群。
**機能は3つ**:選択的タグ付け / オンデマンド抽出 / 統制語彙(taxonomy)。

| ID | 不変則 | 破った場合の害 |
|---|---|---|
| INV-01 | 人間が書くのは `daily/` だけ。複数トピックを1ファイルに混ぜてよい | 入力の習慣が壊れ、記録が止まる |
| INV-02 | 派生物を貯めない。抽出結果はチャットで返す | vault が AI 生成物で膨張し信頼性が落ちる |
| INV-03 | `permanent/` は人間が書いた/編集したノートのみ | 人間の思考と AI の出力が混ざり区別不能になる |
| INV-04 | permanent 化・taxonomy 変更は常に人間が決める | 承認制が崩れる |
| INV-05 | AI の L1 への書き込みは frontmatter の `tags` / `tagged` のみ。本文不可侵 | 外部記憶の信頼性が失われる(最重要) |
| INV-06 | pull 型のみ。scheduled task / push 型自動実行を使わない | v1〜v4 で失敗して全廃した構造に戻る |
| INV-07 | 出力は日本語(technical 語は英語可) | — |
| INV-08 | 新しい欲求には skill を1枚足して対応する(自動化を足さない) | INV-06 の侵食 |

## §2 レイヤモデルと書き込み権限

```
L1 資料層(準不可侵)  daily/ permanent/     ← 本文は人間のみ。AI は frontmatter の tags/tagged のみ
L2 モデル層(承認制)  _meta/taxonomy.md     ← 変更の決定は常に人間
L3 派生層(原則なし)  references/           ← 人間が残すと決めた AI 生成物のみ隔離
L4 エンジン(交換可)  _meta/skills/ _meta/agents/
```

| `daily/**` frontmatter `tags` `tagged` | ○ | △ | `$tag-dailies` 実行時、または直接依頼時のみ |
| `daily/**` チェックボックス状態 | ○ | **×** | 完了マークは人間が行う |

## §4 skills

起動記法は `$<name>`(`/` は各ツールのコマンドと衝突するため使わない)。
呼ばれたら `_meta/skills/<name>.md` を読み、その手順に従う。**自動発見の有無にかかわらずそうする。**

| skill | 役割 | 書込 | 特記 |
|---|---|---|---|
| `$tag-dailies` | `daily/untagged/` に許可タグと `tagged:` を付与し `daily/tagged/` へ移動 | あり | 検証してから移動。新タグは1件ずつ承認を取る |
| `$extract` | タグ+期間で絞った daily を読み、チャットで答える | なし | **未タグ daily は絞り込みに関係なく必ずスキャン**(完全性保証) |
| `$open-todos` | 未完 `- [ ]` の横断ビュー | なし | タスク管理ではなく見落とし防止 |
| `$resurface-ideas` | 行頭 `IDEA:` / `Q:` を grep 回収 | なし | 本文の LLM 読解をしない |
| `$commit` | 差分を確認し、必要なら本ファイルを更新してから git commit | 本ファイルのみ | **push しない。**毎回 SYSTEM.md を更新するわけではない(判定表は `_meta/skills/commit.md`) |
| `$delegate` | 計画/実行の分業モードへ切替 | — | ノートを触らない。作業の進め方を変える skill |

## §5 委譲(delegate)

- サブエージェント対応環境:通常の多段作業→`executor`、設計依存/曖昧な作業→`executor-deep`。行動契約は `_meta/agents/*.md`。
- **非対応環境**:同じタスクブリーフを書き、自分で同じ段階手順で実行する。
- 書き込みを伴う委譲は同時に1件まで。読み取り専用の調査は並列可。
- **委譲は最適化であり要件ではない。vault の機能は1つもこれに依存しない。**

## §6 taxonomy 運用

形式と詳細は `_meta/taxonomy.md` 冒頭。要点のみ:

- `- [x]` = 許可タグ / `- [ ]` = 候補。**承認 = 人間がチェックを付ける、却下 = 行削除**。節間のコピペ移動は存在しない(移動ミスを構造的に排除)。
- skill ができるのは候補行の追記まで。追加・統合・改名の決定は常に人間。
- 改名・統合の既存ノートへの反映は grep/sed の**機械置換**(LLM で本文を再読しない=トークン消費ほぼゼロ)。
- 新タグは前向き適用が既定。遡及タグ付けは人間の明示依頼時のみ(期間指定つき)。
- 保留候補は `$tag-dailies` 実行時に**1件だけ**問われて消化される(pull 型でも承認が回る仕掛け)。
- 粒度の原則:何にでも付くタグを作らない。
- frontmatter は inline 形式(`tags: [type/daily, finance/equity-research]`)が正。

| 人間の発話 | 動作 | 書込 |
|---|---|---|
| 「todo / 残ってるタスク見せて」 | `$open-todos` | なし |
| 「アイデア / 未解決の問いを拾って」 | `$resurface-ideas` | なし |

| 「タグ付けして」「未処理のデイリー処理して」 | `$tag-dailies` | あり |
| 「コミットして」「git に保存して」「週次のコミット」 | `$commit` | あり(本ファイルのみ) |
| 「委譲して」「executor に任せて」 | `$delegate` | — |
| 「これをノートにして」 | 提案 → 人間の承認 → `permanent/` | 承認後 |

| 状態確認・検索・retrieval 全般 | read-only で答える | なし |
| 曖昧な依頼 | 確認は**1つだけ**聞く。それ以上聞かない | — |

## §9 運用フロー

1. **書く**:daily に自由記述。複数トピックを混ぜてよい。これだけが習慣。任意で行頭マーカー `IDEA:` / `Q:`。
2. **デイリー以外を書いた**:`inbox/` に落ちる。溜めずに、人間が編集して残すなら `permanent/`、AI 生成のままなら `references/`。
3. **タグ付け**:思い出した時に `$tag-dailies`。taxonomy の保留判断を1件だけ問われる。
4. **抽出**:聞きたい時に `$extract`。残すかは人間が判断。
5. **permanent 化・taxonomy 更新**:常に人間。
6. **コミット**:週1目安で `$commit`。差分が構成を変えていれば本ファイルも同じコミットで更新される。push は常に人間。

## §10 移植性契約

**合格条件**:ファイルを読める・検索できる・書けるだけのエージェントが、`AGENTS.md` だけを渡されて全機能を実行できること。これを満たさない変更は入れない。

| 層 | 実体 | ベンダ依存 |
|---|---|---|
| 入口 | `AGENTS.md`(正)、`CLAUDE.md` は1行ポインタ | なし(必須) |
| 挙動 | `_meta/skills/*.md`、`_meta/agents/*.md` | なし(正本) |
| 発見 | `.agents/` `.claude/` `.codex/` のスタブ | ツール固有(任意) |

- 完全なベンダ中立は不可能(自動発見・サブエージェント・推論強度は実行環境の能力そのもの)。目指すのは中立化ではなく、**依存部分を「あれば使う最適化」に閉じ込めること**。
- スタブが複製してよいのは frontmatter の `name` / `description` だけ。手順は絶対に複製しない。正本の `description` を変えたら各スタブの1行も揃える(**唯一のドリフト面**)。
- **新しいツールを迎える手順**:①入口ファイルを `AGENTS.md` への1行ポインタとして置く ②(任意)発見パスに `_meta/` を読ませるだけのスタブを置く。これ以上のことはしない。

## §11 保全・スケール・テンプレート

- **版管理**:vault を git 管理。`.gitignore` 配置済み。init は 2026-08-10 に vault 直下で実行済み。コミットは週1目安で `$commit`。リモートへの push は常に人間が行う(skill は push しない)。
- Obsidian の File Recovery(コアプラグイン)を有効にしておく。
- **スケール**:タグ絞り込み後の対象が目安 30 枚を超えたら期間の併用を必須にする。同一タグが恒常的に太る場合は、核を `permanent/` に圧縮して daily を読む頻度を下げる。
- **容量**:テキストのみなら実質問題にならない(年間数 MB)。画像・PDF は vault に貯めず外部リンク or 別管理。
- **空の日**:何も書かなかった日のファイルは残さない(削除してよい)。空のまま残っても `$open-todos` は本文の無いチェックボックス行を無視する。
